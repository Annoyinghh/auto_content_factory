# Windows 工作台发布验收

解压 `AutoContentFactory-Studio-WPF-Win64.zip`，双击 `AutoContentFactory-Studio.exe`。适用 Windows 10 或 11 x64，需系统 .NET Framework 4.8 或更新版。Python 后台、FFmpeg 和抖音投稿助手随包提供。抖音面板需要 Microsoft Edge WebView2 Runtime，本机 AI 需要 Ollama 和可用模型。已有便携模型可保留在同级 `local-ai`。

个人采集、稿件和平台账号继续保存在当前 Windows 用户的数据目录。团队成员使用同一 HTTPS 地址和管理员签发的个人连接码。团队运营共享矩阵、投稿状态和主动提交的算力任务。团队审片只在用户选择送审后上传指定成片。

## 启动对比

在同一台 Windows 11 电脑上轮流启动旧 Tk 版和 WPF 版，每轮使用新的测试数据目录。主窗口计时从启动进程到系统识别到窗口。自检计时还包含页面切换、后台读取和 FFmpeg 检查。

| 测量项 | 旧 Tk 版中位数 | WPF 版中位数 |
| --- | ---: | ---: |
| 主窗口出现 | 4.87 秒 | 0.21 秒 |
| 自检完成 | 13.79 秒 | 1.17 秒 |

首次测试启动分别是 6.71 秒和 1.19 秒。可用 `windows/compare_startup.ps1` 在其他 Windows 机器上复测。

## 发布检查

- 完整 ZIP 在全新目录解压后，去掉开发环境的 Python 路径，验证七个原生页面、本机采集快照和随附的 FFmpeg。
- 从解压包读取文案案例和中文 Windows 上已有的定时任务，验证兼容性。测试未更改定时任务。
- 用隔离的报道、笔记和图片验证选择分支、保留讲述重点、生成试剪、保存分镜和导出。小红书测试成片为 60.9 秒竖屏视频，已验证作品库和发布队列能读取。
- 在隔离的 Cloudflare 本机运行环境验证两位成员的分片上传、下载、审片、并发修订、撤销连接码、R2 三项限额，以及共享矩阵和私有算力结果。
- 已有生产团队运营服务可通过 HTTPS 和现有成员连接码读取。生产团队审片需管理员确认 R2 账户用量和权限后部署，见 [Cloudflare 团队审片](cloudflare-team.md)。
- 发布包当前没有 Authenticode 签名。正式分发前按团队要求确定签名和下载渠道，在另一台不同网络的 Windows 电脑用独立连接码完成验收。

## 异地验收

通过确定的团队渠道一起发送 ZIP、同名的 `.sha256` 文件和 `verify_team_client.ps1`。校验文件应来自发布人员确认的版本。两位测试者在不同网络的 Windows 电脑上分别解压工作台，然后用各自的个人连接码配置团队运营和团队审片。

两台电脑都可以用下面的命令验证同一份发布包。启动自检在临时用户目录中运行，团队连接检查只读取当前 Windows 用户已配置的连接。

```powershell
.\verify_team_client.ps1 -Package .\AutoContentFactory-Studio-WPF-Win64.zip -Checksum .\AutoContentFactory-Studio-WPF-Win64.sha256 -CheckOperations -CheckReview
```

报告包含 ZIP 的 SHA-256、原生启动自检、签名和两项连接状态。回传报告时无需附带连接码、成员信息或内容数据。团队审片地址尚未部署时，可先加 `-CheckOperations` 验证生产运营，等审片可用后再运行两项检查。

1. 核对两份报告的 SHA-256 一致，并且原生自检和两项团队连接均为 `passed`。
2. 制作成员送审一条获准用于验收的测试片。审核成员在另一台电脑播放同一条视频，核对标题和文案，留言并通过。
3. 制作成员刷新后核对留言和通过记录。管理员撤销审核成员的临时连接码，确认该成员重新检查时无法读取审片列表。

上述三步完成后，在上线记录写明验收日期、发布包 SHA-256 和参与验收的两台设备。正式给团队使用时，管理员为每位成员单独签发连接码。
